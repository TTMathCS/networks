# 10. IPv6

*IPv6 gives every device its own address again: 128 bits instead of 32. This chapter explains the address format and types, the simpler header, how hosts configure themselves without DHCP, Neighbor Discovery, and how the internet is moving from IPv4 to IPv6.*

!!! abstract "In this chapter"
    **You will learn:** writing and shortening IPv6 addresses; global, link-local and unique local addresses; the
    40-byte header and extension headers; SLAAC and DHCPv6; Neighbor Discovery; dual stack, NAT64 and other
    transition methods; how much of the internet uses IPv6.

    **You need:** [Chapters 8 and 9](08-IPv4-Addressing-and-Subnets.md).

## 10.1 Writing addresses

An IPv6 address is 128 bits, written as eight groups of four hex digits:

```
2001:0db8:0000:0000:0000:ff00:0042:8329
```

Two rules shorten it: drop leading zeros in each group, and replace **one** run of all-zero groups with `::`:

```
2001:db8::ff00:42:8329
```

`2001:db8::/32` is reserved for documentation. Prefixes work as in IPv4: `2001:db8:1234:5600::/56`.

There are $2^{128} \approx 3.4 \times 10^{38}$ addresses. The standard practice is that every **subnet is a /64**
(64 bits of network, 64 bits for the interface), and a home or small site gets a /56 or /48 from its ISP: 256 or 65,536
subnets.

## 10.2 Kinds of address

| Type | Prefix | Meaning |
| --- | --- | --- |
| Global unicast | `2000::/3` | public, routable, like a public IPv4 address |
| Link-local | `fe80::/10` | valid only on one link; every interface always has one |
| Unique local (ULA) | `fc00::/7` (in use: `fd00::/8`) | private, like RFC 1918 |
| Multicast | `ff00::/8` | e.g. `ff02::1` all nodes on the link, `ff02::2` all routers |
| Loopback | `::1` | the host itself |
| Unspecified | `::` | "no address yet" |

There is **no broadcast** in IPv6; multicast to specific groups replaces it. An interface normally has several
addresses at once: link-local, one or more global, maybe a ULA.

## 10.3 A simpler header

The IPv6 header is a fixed 40 bytes:

| Field | Bits | Notes |
| --- | --- | --- |
| Version | 4 | 6 |
| Traffic class | 8 | like DSCP and ECN |
| Flow label | 20 | lets routers keep a flow's packets on one path |
| Payload length | 16 | |
| Next header | 8 | what follows: TCP (6), UDP (17), ICMPv6 (58), or an extension header |
| Hop limit | 8 | the TTL, renamed honestly |
| Source, destination | 128 + 128 | |

Gone: the header checksum (links and transport already check), fragmentation fields (only the source fragments, using
an extension header), and options in the main header. Optional features live in a chain of **extension headers**
(hop-by-hop, routing, fragment, destination options, IPsec), each naming the next. Fixed size and no checksum make
hardware forwarding simpler; in practice, packets with unusual extension headers are often dropped by middleboxes.

## 10.4 Configuring itself: SLAAC

IPv6 hosts can configure themselves without any server. **Stateless address autoconfiguration** (SLAAC, RFC 4862):

1. The host makes a link-local address `fe80::` + a 64-bit interface identifier.
2. It checks no one else uses it (**duplicate address detection**).
3. It listens for (or asks for) a **Router Advertisement** from the router, which announces the subnet's /64 prefix,
   whether to use DHCPv6, and itself as default gateway.
4. It forms global addresses: prefix + interface identifier.

The interface identifier was once derived from the MAC address (EUI-64), which let anyone track a laptop across
networks. Hosts now use **stable random** identifiers per network (RFC 7217) and short-lived **temporary addresses** for
outgoing connections (RFC 8981). DNS server addresses come in the Router Advertisement (RFC 8106) or from
**DHCPv6**, which can also assign addresses when an organisation wants to track them. Routers get whole prefixes from
their ISP by **DHCPv6 prefix delegation**.

## 10.5 Neighbor Discovery

**Neighbor Discovery Protocol** (NDP, RFC 4861) does ARP's job and more, using ICMPv6:

| Message | Job |
| --- | --- |
| Router Solicitation / Advertisement | find routers and the prefix |
| Neighbor Solicitation / Advertisement | resolve an address to a MAC address (sent to a *solicited-node* multicast group, not to everyone), detect duplicates, check a neighbour is still alive |
| Redirect | point to a better first hop |

Like ARP, NDP trusts what it hears. A fake Router Advertisement can make every host route through an attacker; switches
filter them with **RA Guard** (RFC 6105).

## 10.6 Getting from IPv4 to IPv6

IPv6 cannot talk to IPv4 directly, so the change has taken decades and uses several methods:

- **Dual stack**: hosts and networks run both. Clients prefer IPv6 but race the two (**Happy Eyeballs**, RFC 8305) so a
  broken IPv6 path never delays users.
- **Tunnels**: IPv6 packets carried inside IPv4 (6in4, 6rd) across networks that lack IPv6.
- **IPv6-only with translation**: mobile networks now often give phones only IPv6. A **NAT64** gateway translates to
  IPv4 servers, and **DNS64** invents IPv6 addresses for IPv4-only names (`64:ff9b::/96` + the IPv4 address).
  **464XLAT** (RFC 6877) lets IPv4-only apps on the phone work too.
- **IPv4 as a service** over IPv6 networks (MAP-T, DS-Lite) for home broadband.

Adoption: Google measures that a little under half of its users reach it over IPv6 (about 45–50% in 2025–2026), with
countries such as France, India and Germany above 60% and others far lower. Most large websites and all major mobile
networks support it.

## 10.7 What IPv6 changes, and what not

Every device can have a public address again, so **end-to-end connectivity** returns; firewalls, not NAT, decide what
may come in. Address scanning is impractical (a /64 subnet has $1.8 \times 10^{19}$ addresses), so attackers find hosts
through DNS, logs and multicast instead. Routing, TCP, UDP and applications stay the same.

## Check yourself

??? question "1. Shorten 2001:0db8:0000:0042:0000:0000:0000:0001."
    2001:db8:0:42::1 (the longer zero run becomes ::; only one :: is allowed).

??? question "2. Why is there no ARP in IPv6?"
    Neighbor Discovery, using ICMPv6 and multicast, does address resolution (and router discovery and duplicate detection) instead.

??? question "3. A phone on an IPv6-only network opens an IPv4-only website. What makes it work?"
    DNS64 synthesises an IPv6 address for the name, and a NAT64 gateway translates the packets to IPv4 (with 464XLAT for IPv4-only apps).
